# 디자인 보존 안정성 수정

기준: `ecd82e63eb51b5ad8ec34eb3548a7c2b0c3d41bb` (2026-09-10 확인).
브랜치: `fix/preserve-design-stability`.

## 보존 범위

정적 HTML/CSS/브라우저 ES module 구조, 기존 파일 역할, 모드 진입점,
Test 15문항(3+5+7), Play 5문항·180초, 모바일 분기, 이미지·색상 데이터,
홈·카드·Lab 템플릿, 글꼴·색·간격·레이아웃을 유지했다.
`style.css`의 기존 규칙은 원문 그대로이며 키보드 focus-visible와
사용자의 reduced-motion 설정에만 적용되는 규칙을 끝에 추가했다.
기본 커서·카드·150ms 색상 전환은 유지한다.

의도된 차이는 결과/기록의 문구, 메타 설명, 튜토리얼 임계값 35→40,
키보드 포커스·조작 의미, 오류 안내와 잘못된 동작의 수정이다.
결과·기록은 기존 템플릿과 색상 체계 안에서 표현한다.
이들 문구는 기존 화면과 글자까지 동일하다고 주장하지 않는다.

## 재실행

Node 22, npm, git이 필요하다.

```sh
npm ci
npx playwright install chromium
npm run verify
```

Linux CI의 브라우저 시스템 패키지는 `npx playwright install --with-deps chromium`으로 설치한다.

- `npm run build:css`: 기존 Tailwind 3 계열로 CSS 생성.
- `npm run test:unit`: 실제 모듈 기반 상태·채점·저장·이미지·디자인 계약 테스트.
- `npm run test:e2e`: Chromium에서 실제 DOM/브라우저 동작 검증.
- `npm run test:visual`: 고정 기준 commit과 현재 코드를 같은 환경에서 렌더·비교.
- `npm run verify`: 위 검증을 순서대로 실행.

서버는 loopback의 `/MY-ColorVision/` 하위 경로에서 동작한다.
테스트용 저장소·난수·이미지·시간 조작은 분리된 테스트 브라우저에만 적용한다.
실제 사용자 localStorage를 읽거나 변경하지 않는다.

## 화면 하네스

2026-09-10 로컬 검증: 단위 32/32, 실제 Chromium 브라우저 24/24 통과.
아래 26개 장면의 검출된 차이 픽셀 합계 0, pageerror 0.
실제 배포와 같은 Sortable 1.15.6의 첫 칸→마지막 칸 드래그·정리도 확인했다.
GitHub Actions 실행 결과는 해당 commit의 Quality gates에서 별도로 확인한다.

데스크톱 1440×900, 태블릿 768×1024, 좁은 데스크톱 390×844,
iPhone UA/touch/no-hover 환경 390×844를 별도로 검증한다.

26개 정적 장면은 홈, RGB 교육, 카드, 숫자 판독, 정렬, RGB, 빈 Lab 화면이다.
기존 모바일 홈에 없는 교육/카드 장면은 임의로 만들지 않는다.
원본은 git archive로 추출하고, 현재 화면을 새 기준으로 덮어쓰지 않는다.
기준 commit을 사용할 수 없으면 시각 검증은 실패한다.

애니메이션 이름을 없애지 않고 짧은 시간으로 완료시켜 최종 프레임을 촬영한다.
실제로 표시되는 제목/단계 글자가 있는지도 검사해 투명한 화면끼리 비교하지 않는다.
움직이는 커서 canvas만 촬영에서 숨기며, 기본 커서/모션 동작은 별도 E2E로 확인한다.
pixelmatch threshold 0.1에서 검출된 차이 픽셀은 0이어야 한다.
이 수치는 브라우저 렌더의 바이트 동일성을 뜻하지 않는다.

스크린샷·차이 이미지·JSON 보고서는 `artifacts/visual/`,
브라우저 보고서는 `playwright-report/`에 생성된다.
색상 전환 중 실제 표시색, 모바일 RGB 반복 탭, 이미지 업로드 이후 화면,
기록 모달은 동작 테스트로 보완한다.
결과·기록 문구는 의도적으로 바뀌므로 26개 무차이 장면에 포함하지 않는다.

공개 폰트/CDN 자산은 같은 실행의 양쪽 화면에 동일한 캐시로 제공한다.
시각 검증은 최초 실행 때 공개 자산 다운로드가 필요하다.
기능 E2E는 외부 CDN 없이도 실행되도록 별도 차단 환경을 사용한다.

## 범위를 넓히지 않은 항목

사용자의 “디자인이 바뀌면 안 된다”는 요청에 따라 다음은 이번 패치에서 보존했다.

- 일반 UI의 색 대비·폰트 크기·레이아웃 변경.
- 모바일 Home에 Play/교육 영역을 새로 노출하는 화면 변경.
- 숫자 판독 선택지 추가와 검사 이미지의 기존 합성 효과 변경.
- 홈 교육 데이터·유병률·조합 설명의 전면 수정 및 새 출처 영역 추가.

따라서 기존 교육 설명의 정확성 문제와 일부 낮은 대비는 해결됐다고 주장하지 않는다.
결과의 진단 단정은 제거했지만 홈/튜토리얼의 교육 문구 전체를 검증한 패치는 아니다.
임상 선별 성능, 색각 시뮬레이션 모델 유효성, 새 지각 난도 설계,
공용 서버 리더보드는 별도 과제다.

이미지 원본 해상도 검사는 디코딩 직후 Canvas 할당 전에 한다.
압축 이미지 디코딩 자체의 메모리 사용량을 사전에 완전히 제한하지는 않는다.
실제 휴대전화 하드웨어·Safari·Firefox 전체와 WCAG 전체 적합성은 별도 검증이 필요하다.

## 복구

이 브랜치는 main과 운영 배포를 직접 변경하지 않는다.
병합 전에는 이 브랜치를 배포하지 않는 것으로 운영 원본이 유지된다.
병합 후 복구가 필요하면 이 변경 commit만 revert하고 CSS도 함께 되돌린다.
기록 저장 형식은 기존 key `colorLeaderboard`를 유지하며 기존 항목을 삭제하지 않는다.
